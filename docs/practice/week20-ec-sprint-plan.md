# ECサイト スプリント計画（練習課題1）

## 前提
- 1スプリント：2週間
- ユーザーストーリーは docs/practice/week18-user-stories.md を使う
- 優先度は MoSCoW（Must / Should / Could / Won't）で付けた

## ユーザーストーリーの優先度

### 買い物をするユーザー
| ストーリー | 優先度 | スプリント |
|---|---|---|
| 1. 住所や支払い方法を登録してログインしたい | Must | 2 |
| 2. 商品をキーワードで探したい | Must | 1 |
| 3. 商品をジャンルごとに見たい | Must | 1 |
| 4. 商品の詳細を見たい | Must | 1 |
| 5. 気になる商品をお気に入りに登録したい | Won't | 次回以降 |
| 6. ほかの人のレビューを見たい | Won't | 次回以降 |
| 7. 欲しい商品をカートに入れたい | Must | 2 |
| 8. カートの商品をサイト上でそのまま支払いたい | Must | 2 |
| 9. 注文後に確認メールを受け取りたい | Should | 3 |
| 10. 注文履歴を見たい | Should | 3 |

### お店の管理者
| ストーリー | 優先度 | スプリント |
|---|---|---|
| 1. 商品ページを作成・編集したい | Must | 1 |
| 2. 商品のカテゴリを管理したい | Must | 1 |
| 3. 商品の在庫数を管理したい | Must | 2 |
| 4. 入った注文を確認して発送済みにしたい | Must | 2 |
| 5. お客さんが配送状況を自分で確認できるようにしたい | Should | 3 |
| 6. 返品・キャンセルに対応したい | Must | 3 |
| 7. 割引クーポンを発行したい | Won't | 次回以降 |
| 8. 売上を確認したい | Must | 3 |
| 9. 不適切なレビューを非表示・削除したい | Won't | 次回以降 |
| 10. 問題のある会員を利用停止にしたい | Could | 次回以降 |

## スプリント1
**ゴール：お客さんが商品を探して、詳細を見られる**

| ストーリー | 理由 |
|---|---|
| 管理者1. 商品ページを作成・編集したい | 商品がないと、ほかの機能が何も動かない |
| 管理者2. 商品のカテゴリを管理したい | ジャンルごとに見るには、先にカテゴリが必要 |
| 買い物3. 商品をジャンルごとに見たい | 登録した商品をお客さんが見られるようにする |
| 買い物2. 商品をキーワードで探したい | 商品が増えたときに探せるようにする |
| 買い物4. 商品の詳細を見たい | 買うかどうか判断するのに必要 |

## スプリント2
**ゴール：お客さんがログインして商品を買える。お店が商品を発送できる。**

| ストーリー | 理由 |
|---|---|
| 買い物1. 住所や支払い方法を登録してログインしたい | 誰が買うのか分からないと注文できない |
| 管理者3. 商品の在庫数を管理したい | 売り切れの商品を注文されないようにする |
| 買い物7. 欲しい商品をカートに入れたい | 複数の商品をまとめて注文するため |
| 買い物8. カートの商品をサイト上でそのまま支払いたい | 買い物を完了させるため |
| 管理者4. 入った注文を確認して発送済みにしたい | 注文が入ったあと、お店が発送するため |

## スプリント3
**ゴール：お客さんが商品を買ったあとも安心して使える。お店が運営しやすくなる。**

| ストーリー | 理由 |
|---|---|
| 管理者6. 返品・キャンセルに対応したい | 商品が届いたあとに起きるため、発送の仕組みのあとに作る |
| 管理者8. 売上を確認したい | 注文がたまってから意味が出る機能のため |
| 買い物9. 注文後に確認メールを受け取りたい | 注文が完了したか不安にならないようにする |
| 買い物10. 注文履歴を見たい | 気に入った商品をもう一度買えるようにする |
| 管理者5. お客さんが配送状況を自分で確認できるようにしたい | 問い合わせの手間を減らす |

## 次回以降に回すもの
- 買い物5. お気に入り（Won't：なくても買い物はできる）
- 買い物6. レビューを見る（Won't）
- 管理者9. 不適切なレビューの削除（Won't：レビュー機能を作らないため、一緒に次回以降にする）
- 管理者7. 割引クーポン（Won't：まず通常の販売ができることを優先する）
- 管理者10. 会員の利用停止（Could：会員が少ないうちは問題が起きてから対応しても間に合う。スプリント3に余裕があれば入れる）
