# 技術選定資料

## 2. デプロイ先

### 選んだもの：A（AWS を使い続ける）

| | A：AWS を使い続ける | B：Render などに Docker で出す |
|---|---|---|
| 構成 | EC2 ＋ Docker ＋ GitHub Actions（Week 11〜16 の構成） | Render などのサービスに Docker で出す |
| 費用 | 無料プランのクレジットの範囲（残り約108ドル） | 無料プランあり |
| データベース | RDS（Week 13 で作成済み） | 無料の DB は30日で使えなくなることがある |
| 画像 | EC2 内に保存でき、消えない | アップロードした画像が消える |
| 作業 | 構成ができているので、切り替えだけで済む | 新しいサービスの使い方を覚える必要がある |

### 選んだ理由
1. **写真が消えないから**：gohan-log は食事の写真が中心のアプリで、写真が消えると記録として使えなくなる。
2. **作った構成を使い回せるから**：Week 11〜16 で EC2・Docker・GitHub Actions の自動デプロイを作ってあり、実装期間（約26.5時間）の中でデプロイに使う時間を減らせる
3. **費用の範囲に収まるから**：クレジットが約108ドル・2027年3月1日まで残っていて、提出・レビュー期間だけ動かせば十分足りる

構成図は docs/05_infrastructure/infrastructure.md を参照。

## 3. 今回使わない技術と理由
| 技術 | 理由 |
|---|---|
| API とフロントエンドを分ける構成（React・Vue） | 発展（任意）のため。実装期間が短いので、Blade の構成で必須の機能を確実に作る |
| S3（画像の保存先） | 発展のため。Week 17 で使ったが、設定が増えるので余裕があれば対応する |
| 料金がかかる外部 API（AI 分析など） | 予算が学習用（無料の範囲）のため |
